# 模型评估诊断报告：电损伤/物理损伤召回率未达标归因分析

| 项目 | 内容 |

| 项目名称 | 光伏面板缺陷检测系统 |
| 文档类型 | 诊断报告（阶段2评估问题归因） |
| 编写日期 | 2026-09-18 |
| 关联文档 | model_eval_report.md（评估报告模板）、spec.md、prd.md |
| 评估对象 | runs/detect/runs/train_n2/weights/best.pt（YOLOv8n，early-stop@epoch72） |

## 1 问题现象

工程口径评估（工作点 conf=0.25、IoU=0.5，与部署阈值一致）测试集结果：

| 指标 | 实测 | 验收线 | 结论 |
|---|---|---|---|
| mAP@0.5（工程口径） | 0.8199 | ≥0.75 | 达标 |
| mAP@0.5（官方口径） | 0.8951 | ≥0.75 | 达标 |
| Electrical-damage（电损伤）召回率@0.25 | 0.7000（7/10） | ≥0.80 | **未达标** |
| Physical-Damage（物理损伤）召回率@0.25 | 0.7143（5/7） | ≥0.80 | **未达标** |
| 其余缺陷类（积灰/鸟粪/积雪）召回率 | 0.8947/0.9048/0.9167 | ≥0.80 | 达标 |

未达标集中在**局部型缺陷**（电损伤热斑、物理损伤裂纹），全局型缺陷（积灰、鸟粪、积雪）均达标。

## 2 诊断过程

### 2.1 第一步：隔离推理参数（结论：参数无关）

在 `runs/eval/diag_nms07` 重跑工程口径，参数偏离部署配置以观察召回是否恢复：

| 参数 | 部署配置 | 实验配置 |
|---|---|---|
| 工作点置信度 conf | 0.25 | **0.05**（远低于部署） |
| NMS IoU | 0.45 | **0.7** |
| 收集阈值 collect-conf | 0.01 | **0.001** |

结果：电损伤 R=0.7000、物理损伤 R=0.7143，与 0.25 阈值下**完全一致**（逐类 AP、工作点指标均无变化）。

结论：**漏检与置信度阈值、NMS IoU 无关**。模型在极低阈值下也没有输出与 GT 匹配的检测框，参数调优无法修复。

### 2.2 第二步：定位漏检图像并核对模型输出（结论：类别混淆）

漏检固定为 5 张图（conf=0.001 低阈值单图推理，列出全部检测）：

| 图像 | GT 类别 | 人工内容核查 | 模型最高置信输出 | 置信度 |
|---|---|---|---|---|
| Electrical-damage (67) | 电损伤 | 中央焦黄色热斑损伤 | **Bird-drop（鸟粪）** | 0.95 |
| Electrical-damage (75) | 电损伤 | 清洁残留灰白色条纹 | **Clean（清洁）** | 0.51 |
| Electrical-damage (83) | 电损伤 | 与 (75) 重复图，内容一致 | **Clean（清洁）** | 0.51 |
| Physical-Damage (41) | 物理损伤 | 中央穿刺孔洞及放射状裂纹 | **Clean（清洁）** | 0.73 |
| Physical-Damage (53) | 物理损伤 | 边缘撕裂状破损及灰白色条纹 | **Clean（清洁）** | 0.97 |

关键事实：模型**检测到了缺陷区域**（输出高置信度框），但**类别判断错误**——电损伤热斑被判为鸟粪、物理损伤被判为清洁。由于评估按类别匹配（电损伤检测只与电损伤 GT 匹配），类别错置导致该类下无匹配框 → 必然漏检。

### 2.3 第三步：数据集标签质量核查（结论：标签系统性失真）

对 `datasets/labels/` 全量标签做全幅占位框（`0.5 0.5 1.0 1.0`）统计：

| split | 文件数 | 标签总数 | 全幅占位框 | 占比 |
|---|---|---|---|---|
| train | 1409 | 2015 | 1207 | 59.9% |
| val | 88 | 88 | 88 | 100% |
| test | 88 | 88 | 88 | 100% |

5 张漏检图标签实测均为 `3 0.5 0.5 1.0 1.0` / `4 0.5 0.5 1.0 1.0` 全幅框。

附加发现（md5 查重，共 273 组重复文件）：

- test 集内部 (75) 与 (83) 为重复图（后者漏检由此而来）；
- test 与 train 存在跨集重复（如 `test/Dusty_Dust (25)` = `train/Dusty_Dust (83)` 等），存在数据泄漏风险；
- 大量增强样本 `augm_*` 两两相同（augment 抖动不足或复制）。

### 2.4 第四步：排除评估口径/状态污染干扰

双口径对照与状态污染实验（diag_tensor4）：直接 val、先 predict 后 val、eval 后 val、train 后 val 四种场景 mAP50 均为 0.8951、电损伤 R=0.7000、物理损伤 R=0.7954，指标稳定复现 → 排除模型状态、评估顺序干扰。

## 3 根因结论

1. **测试集/验证集标签系统性失真**：val/test 全部 88 张图标签均为全幅占位框，未标注局部缺陷的真实位置。模型训练（train 集 60% 全幅框）学到的是"**整幅图纹理 → 类别**"的全局模式，而非"**局部缺陷 → 类别**"的定位模式；
2. **局部缺陷类别混淆**：对电损伤热斑、物理损伤裂纹这类局部小目标，模型输出高置信但类别错误的框（鸟粪/清洁），是召回率未达标的直接原因；
3. **评估结果可信度受损**：由于 test 标签本身为占位框，当前评估结果（无论达标项）均不能代表模型对真实局部缺陷的检测能力；测试集评估在此标签下失真。

## 4 已排除的候选方案（证据）

| 方案 | 结论 | 证据 |
|---|---|---|
| 降低部署置信度阈值 | 无效 | conf 0.05 与 0.25 下召回率完全一致（2.1） |
| 调整 NMS IoU | 无效 | 0.45→0.7 指标无变化（2.1） |
| 修正评估口径/预处理 | 无效 | 双口径仅解释 mAP 偏差（0.0753），召回率两类口径均未达标；官方口径下物理损伤 0.7954 仍略低于 0.80 |
| 模型状态污染 | 排除 | 四场景指标稳定复现（2.4） |

## 5 建议修复方案（根治路径）

1. **人工标注局部缺陷框**：对 train 集 1207 个全幅占位框（重点：电损伤/物理损伤类，约350个）及 val/test 全部标签，替换为实际缺陷位置的精确坐标；可用当前模型伪标注辅助定位后人工复核，降低标注工作量；
2. **清理重复文件**：删除 train 内部及跨 split 的 md5 重复文件，确保 train/val/test 无数据泄漏；
3. **重新训练**：修正标签后重跑 train.py（迁移学习、加权采样、early-stop），再按 eval.py 双口径评估验证电损伤/物理损伤召回率是否恢复至 ≥80%；
4. **更新评估报告**：达标后重新生成 model_eval_report 归档。

## 6 备选方案（不重训时的定稿口径）

若项目周期不允许重标重训，评估报告须如实声明：

- mAP@0.5=0.8199（工程）/0.8951（官方）达标；
- 电损伤、物理损伤召回率未达标且**已归因于测试集标签失真**（全幅占位框与局部缺陷不符），当前测试集指标不能反映模型真实能力；
- 验收按任务书口径判定为**存在未达标项**，需在交付说明中明示数据标注质量限制与后续整改计划。
